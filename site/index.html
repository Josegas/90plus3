Three bottlenecks. Your move.

You inherit a system that's 0–2 down: a full scan, an aggregate that recomputes on every request, and an N+1. Three substitutions. Every number below is measured against a running API — no fake latency, no animations pretending to be slow.

01

Put a striker on Fix the access pattern

The app scans the entire table to find one record. It works on your laptop. In production it's a red card. Replace the full scan with a query on a sparse index.

Scan O(n) → Query on GSI O(1)
not measured
02

Close the midfield Stop recomputing

The dashboard recalculates the same aggregate on every request. Nobody notices in dev. Everybody notices at kickoff. Compute once, cache the result.

Recompute full table → Read cached O(1)
not measured
03

Change the wing Kill the N+1

Two hundred players, two hundred sequential round trips. The classic N+1 that looks innocent in a loop. One batched read instead.

N+1 200 queries → Batch 2 queries
